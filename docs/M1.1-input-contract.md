# M1.1 — Input contract and XML adapter

Build spec for units **U1** and **U2**. Everything here was found by testing real data against the spec; none of it should be rediscovered. Spec references (§n) are to `ref/opps-adjudicator-scope.md` (rev 9 at the time this was written; the spec is now rev 12 — the § numbers below are still correct).

**Scope:** define `ClaimInput`, and build the XML institutional adapter that produces it. No adjudication, no rules, no data tables.

---

## Why this layer is not thin

The instinct is to treat input as plumbing. Four findings from real data say otherwise, and each one silently produces a wrong answer if the adapter gets it wrong.

| # | Finding | Consequence if missed |
|---|---|---|
| 1 | **Institutional claims arrive as XML; only CMS-1500s arrive as JSON.** `837-claim-viewer` has *no XML support at all* — no XML code in `src`, file dialog accepts only `json/dat/edi/txt/837` | There is no parser to reuse for the only claim type this engine handles. This adapter is net-new code, not a wrapper. |
| 2 | **Line id is `remote_chgid`**, not `chgid` (which is what `jsonClaimSource` reads) | All 16 lines of the test claim get `chargeId: ''`, collide, and `bundledUnder` names nothing |
| 3 | **`charge_record_type` is the unit-of-measure qualifier** — `DA` (days) vs `UN` (units) | 6 `DA` of room & board and 746 `UN` of pharmacy are different quantities. Treating units as dimensionless corrupts the 8011 unit test and any future per-unit logic |
| 4 | **Lines carry `rev_code` with no `proc_code`** | Adjudication is keyed on the Status Indicator, a property of a HCPCS code. All 16 lines had none. Normal billing, not an error (§8.0.1) |

Plus: no per-line dates (only `hosp_from_date`), and `claim_form="ub92"` — a value `mapFormType` maps to `'unsupported'`.

## U1 — `ClaimInput` and the vocabularies

`src/types.ts`. The engine defines this itself; it does **not** import from the viewer (§2.1). The viewer's `src/model/claim.ts` is the naming reference so both programs describe a claim the same way.

```ts
export interface ClaimLineInput {
  /** §19.14: chargeId when the feed supplies one, else `idx:<n>`. Unique per claim. */
  lineId: string;
  /** Empty string when the line carries no HCPCS — legitimate, see §8.0.1. */
  procCode: string;
  modifiers: string[];
  /** UB-04 FL42. Present on institutional lines even when procCode is empty. */
  revCode: string;
  /** Raw feed value, unparsed. */
  units: string;
  /** Unit-of-measure qualifier: 'DA' days, 'UN' units, '' unknown. */
  unitQualifier: string;
  chargeMils: number;
  /** YYYYMMDD. Falls back to the claim period when the feed has no per-line date. */
  fromDate: string;
  thruDate: string;
}

export interface ClaimInput {
  claimId: string;
  /** Raw feed value, e.g. 'ub92'. The gate decides; the adapter does not judge. */
  claimForm: string;
  /** UB-04 FL04, e.g. '81A'. Empty when absent. */
  typeOfBill: string;
  statementFrom: string;
  statementThrough: string;
  conditionCodes: string[];
  occurrenceCodes: { code: string; date: string }[];
  valueCodes: { code: string; amountMils: number }[];
  /** NUCC taxonomy of the billing provider, e.g. '282NC0060X'. Gate input. */
  billingTaxonomy: string;
  payer: { id: string; name: string };
  diagnoses: string[];
  lines: ClaimLineInput[];
  /** Feed-declared total, for the §U2 reconciliation check. */
  totalChargeMils: number;
  /** Which lineId scheme was used, so a consumer knows if it holds positional ids. */
  lineIdScheme: 'feed' | 'positional' | 'mixed';
}
```

Also in U1, from §5.1 / §5.3 / §10.3 / §12.7 — declare these as string-literal union types, not enums, so they serialize as themselves:

- `Status` — includes `NO_PROCEDURE_CODE` and `INVALID_HISTORICAL` (rev 8/9 additions)
- `Disposition` — `REJECTED | ROUTED | ADJUDICATED | ENGINE_ERROR`
- `Outcome` — `FIRED | NOT_FIRED | NOT_EVALUATED | NOT_REACHED | SKIPPED | ERRORED | RETIRED` (no `NOT_APPLICABLE`, §5.3a)
- `Basis` — 13 values including `COST`
- `EngineErrorCode`, `EngineError`, `Flag`, `FlagSeverity`

**Money is integer mils** (1/1000 dollar) everywhere. `$2700.00` → `2700000`. Never a float field.

## U2 — the XML adapter

`src/adapters/instXml.ts`. Input is the feed's XML; output is `ClaimInput`.

### Shape

`<claims>` → one or more `<claim>`, attributes flat on the element, repeating `<charge>` children. Isomorphic to the JSON feed's flat-plus-`charge`-array shape, differently serialized — so the field-mapping table is reusable if the feed ever emits institutional JSON.

### Field mapping

| `ClaimInput` | XML source | Notes |
|---|---|---|
| `claimId` | **caller-supplied only**, else `idx:<n>` | Never derived from the feed. See below. |
| `claimForm` | `@claim_form` | observed `ub92`; pass through raw |
| `typeOfBill` | `@type_of_bill` | observed `81A` |
| `statementFrom/Through` | `@hosp_from_date` / `@hosp_thru_date` | dates arrive `YYYY-MM-DD`; normalize to `YYYYMMDD` |
| `conditionCodes` | `@cond_code_1..N` | collect until absent |
| `occurrenceCodes` | `@occ_code_N` + `@occ_date_N_date` | pair by index |
| `valueCodes` | `@value_code_N` + `@value_amt_N` | `value_code 80` = covered days, a §8.0 gate input |
| `billingTaxonomy` | `@bill_taxonomy` | observed `282NC0060X` |
| `payer` | `@payerid`, `@payer_name` | keys the §20 divergence layer |
| `diagnoses` | `@diag_1..N`, `@admit_diag` | |
| `lines[].lineId` | `@remote_chgid` | **not `chgid`.** See below. |
| `lines[].procCode` | `@proc_code` | **absent on institutional rev-only lines → `''`** |
| `lines[].revCode` | `@rev_code` | |
| `lines[].units` | `@units` | raw string, unparsed |
| `lines[].unitQualifier` | `@charge_record_type` | `DA` / `UN` |
| `lines[].chargeMils` | `@charge` | × 1000, integer |
| `lines[].fromDate/thruDate` | *absent* → claim `statementFrom/Through` | the §13.2 fallback is load-bearing here, not optional |

### `claimId` is caller-supplied, never derived from the feed (D7)

Earlier revisions of this document said `claimId` came from `pcn` "or a supplied correlation id" while also listing `pcn` as a field never carried through. That was a straight contradiction, and the stricter rule wins: **`pcn` is a patient control number and the adapter does not read it.**

- `claimId` comes from the caller, via options, positionally matched to the `<claim>` elements.
- With no caller-supplied id, `claimId` falls back to `idx:<n>` — a meaningless but safe positional string.
- **The consequence is real and accepted:** on a live feed with no supplied id, determinations carry no correlation back to the source claim. That is a host responsibility, not an engine one. A host that has decided `pcn` is acceptable in its own context is free to pass it in; the engine never makes that decision on the host's behalf.

This is the general principle for this layer: where a PHI-adjacent field would be convenient, the adapter refuses and the host decides.

### Line identity (§19.14, decision D1)

```
lineId = remote_chgid (trimmed)  when non-empty and unique across the claim
       | 'idx:' + index          otherwise
```

Set `lineIdScheme` accordingly — `'feed'`, `'positional'`, or `'mixed'` if some lines fall back. If two lines resolve to the same `lineId`, throw `EngineError` with code `LINE_ID_NOT_UNIQUE` and a `path` naming both indices. Do not silently de-duplicate: `bundledUnder` pointing at the wrong line is worse than refusing the claim.

### Validation the adapter performs

1. **Total reconciliation.** Sum of `chargeMils` must equal `totalChargeMils`. Verified on the test claim: the 16 lines sum to exactly `9202.07`. A mismatch is a `Flag` at `severity: 'warning'` — not fatal, since a feed may legitimately carry non-covered lines, but never silent.
2. **`lineId` uniqueness** — above.
3. **Date normalization** — `YYYY-MM-DD` → `YYYYMMDD`; an unparseable date is a flag, never a guess.
4. **Money parse** — reject `NaN`. The feed's charges are plain decimals, but apply the same discipline §7.1 requires of the CMS files: no permissive coercion to `null`.

### PHI boundary — allow-list, not deny-list (§2.1, §14)

The adapter is where PHI stops, and it enforces that by **only** reading the fields in the mapping table above. Anything not listed is not read.

Present in the feed and **never** carried through: `pat_name_l/f/m`, `pat_dob`, `pat_sex`, `pat_addr_*`, `pat_city/state/zip`, `ins_number`, `ins_name_*`, `ins_addr_*`, `ins_dob`, `mrn`, `pcn`, `pat_rel`, `bill_npi`, `bill_taxid`, `prov_name_*`, `prov_npi`, `remote_fileid`, `remote_batchid`.

Write a test asserting the adapter's output contains none of these values, so the boundary is enforced mechanically rather than by review. An allow-list that drifts into a deny-list is how PHI leaks.

## Test expectations

Fixture: `../test/fixtures/inst-xml-inpatient-cah-revonly.xml` (already committed, PHI stripped).

U2 must produce a `ClaimInput` where:

- `claimForm === 'ub92'`, `typeOfBill === '81A'`
- 16 lines, **every** `procCode === ''`, every `revCode` populated
- `lineIdScheme === 'feed'`, ids `129543`…`129544`, all unique
- `lines[0].unitQualifier === 'DA'`, `units === '6'`; `lines[1].unitQualifier === 'UN'`, `units === '746'`
- every line's `fromDate === '20200825'` via the claim-level fallback
- `valueCodes` contains `{ code: '80', amountMils: 6000 }`
- `totalChargeMils === 9202070`, and reconciliation passes
- `billingTaxonomy === '282NC0060X'`, `payer.name === 'HUMANA'`
- **no PHI-listed value appears anywhere in the output**

This fixture's *adjudication* outcome is `NOT_OPPS` (§8.0), but that is U12's test. U2 only proves the adapter reads it faithfully.

Add a second, synthetic fixture: an outpatient 13X claim with real HCPCS codes, so U2 has a positive case. Nothing in the folder supplies one — the only real institutional claim available is this inpatient CAH claim, which is itself the finding that motivated §8.0.

## Do not build here

- No `INVALID_HISTORICAL` logic — that is U5 (needs the HCPCS index) and U12.
- No §8.0 gate — that is U12. The adapter reports what the feed says; it does not judge scope.
- No data tables — U3/U4.
- No `formType` normalization to `'ub04'`. Pass `claimForm` through raw and let the gate decide. Mapping `ub92` → `ub04` in the adapter would hide exactly the finding that produced §8.0.
